# CollabMe

**CollabMe** — клиент-серверная информационная система для студентов: профиль, публикация заявок на проекты и поиск соучастников. Мобильный клиент на Android обращается к REST API; данные хранятся в PostgreSQL.


---

## Возможности

| Область | Что реализовано |
|--------|------------------|
| **Аккаунт** | Регистрация, вход по JWT, выход, хранение токена между запусками (DataStore) |
| **Профиль** | Создание и редактирование (ФИО, дата рождения, город, вуз, направление, «о себе», соцсети), просмотр своего и чужого профиля |
| **Заявки** | Список проектов, создание и редактирование своих заявок, детальный экран, мягкое удаление |
| **Отклики** | Добавление заявки в избранное, отзыв отклика, список откликнувшихся для автора заявки |
| **Карточки** | Просмотр чужих заявок в формате «свайп-карточек» (пропустить / детали / отклик) |
| **Офлайн** | Локальный кэш (Room): профиль, список заявок и избранное подтягиваются с сервера и показываются при недоступности сети; на экране карточек — плашка «Нет подключения к сети» |
| **Справочники** | Города, вузы, направления, темы, типы и статусы заявок |

Нижняя навигация в приложении: **Проекты**, **Карточки**, **Избранное**, **Профиль**.

---

## Стек

**Backend:** Kotlin, Ktor 2.x, Netty, kotlinx.serialization, JWT, Exposed, HikariCP, PostgreSQL JDBC, bcrypt  

**База данных:** PostgreSQL 18, Flyway 10, Docker Compose (только БД и миграции)  

**Android-клиент:** Kotlin, Jetpack Compose, Material 3, Navigation Compose, MVI (Intent / State / Effect), Ktor Client, DataStore, Room, Coroutines  

**Архитектура:**
- сервер — feature-модули: Routes → Service → Repository → Exposed;
- клиент — presentation → domain ← data (репозитории поверх API и локального кэша).

## Развёртывание для разработки

### Требования

- [Docker](https://docs.docker.com/get-docker/) и Docker Compose — для PostgreSQL и миграций
- **JDK 17+** — для запуска backend
- **Android Studio** — для сборки и запуска клиента (minSdk 24)

Backend и Android в Compose **не** упакованы: через Docker поднимается только база и применяются миграции.

### 1. База данных (Docker)

Из корня репозитория:

```bash
docker compose up -d
```

Что происходит:

1. Сервис **`db`** — PostgreSQL 18 на хосте **`localhost:5433`** (внутри контейнера порт 5432).
2. Сервис **`flyway`** — после готовности БД применяет миграции из `db/migrations/`.

Параметры по умолчанию (согласованы с `backend/src/main/resources/application.conf`):

| Параметр | Значение |
|----------|----------|
| База | `app_db` |
| Пользователь | `app_user` |
| Пароль | `app_password` |
| JDBC с хоста | `jdbc:postgresql://localhost:5433/app_db` |

Проверка, что контейнер БД жив:

```bash
docker compose ps
```

Повторно применить миграции (например, после добавления новых SQL-файлов):

```bash
./db/migrate.sh
```

Остановить окружение:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker-volume `postgres_data`. Полное удаление данных: `docker compose down -v`.

### 2. Backend (Ktor)

При работающей БД:

```bash
cd backend
./gradlew run
```

API по умолчанию: **http://localhost:8080**


### 3. Android-клиент

1. Откройте каталог **`frontend/`** в Android Studio.
2. Соберите и запустите модуль **`app`** на эмуляторе или устройстве.

Базовый URL API задаётся в `frontend/app/src/main/java/com/example/collabmefrontend/core/network/ApiClient.kt`:

- **Эмулятор Android:** `http://10.0.2.2:8080` (указано по умолчанию) — это `localhost` вашей машины.
- **Физическое устройство:** замените на IP компьютера в локальной сети, например `http://192.168.1.10:8080`, и убедитесь, что порт 8080 доступен с телефона.

На эмуляторе для HTTP к dev-серверу в манифесте включён `usesCleartextTraffic` (только для разработки).

## Типичный порядок первого запуска

```bash
# 1. БД + миграции
docker compose up -d

# 2. API (отдельный терминал)
cd backend && ./gradlew run

# 3. Приложение — из Android Studio (Run app)
```

Далее: регистрация → заполнение профиля → создание или просмотр заявок в разделах «Проекты» / «Карточки» / «Избранное».

## Ограничения текущей версии

- Logout только на клиенте (JWT без серверного blacklist).
- Навыки (`profile_skills`, `theme_skills`) заложены в схеме БД; UI может быть расширен позже.
- Операции записи (регистрация, сохранение профиля, отклики) требуют сети; офлайн-режим ориентирован на **просмотр** ранее закэшированных данных.
